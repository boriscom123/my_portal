# Свой сервер Telegram Bot API

Бот, который ходит в облако Telegram, отдаёт файл **не больше 50 МБ**. Урок
весит сотни. Свой сервер Bot API снимает этот предел до **2000 МБ** — и это
единственный способ отдать зрителю запись урока целиком прямо в мессенджер.

Что меняется у портала, когда сервер поднят:

| Что | Через облако | Через свой сервер |
|---|---|---|
| Видео урока в канал | режется по 50 МБ | режется по 2000 МБ |
| «Загрузить видео в Telegram» | откажет на большом уроке | загрузит целиком |
| Бот отдаёт урок зрителю | нечего отдавать | отдаёт по `file_id` мгновенно |

Всё остальное — вход на сайт, уведомления, анонсы в канал — работает одинаково
и без своего сервера. Поднимать его стоит ради видео.

## 1. Ключи с my.telegram.org

Серверу нужны `api_id` и `api_hash` — они выдаются **личному аккаунту**, а не
боту.

1. https://my.telegram.org → войдите по номеру телефона.
2. «API development tools» → заполните короткую форму (название и адрес — любые,
   их видите только вы).
3. Со страницы заберите `App api_id` и `App api_hash`.

> Это ключи вашего аккаунта. Не публикуйте их, не отправляйте в переписке и не
> вставляйте в файлы, которые уходят в репозиторий: `.env` в git не попадает, а
> история чата — попадает.

## 2. Запуск

Сервер уже описан в `docker-compose.yml` этого проекта под профилем
`standalone`. Впишите ключи в `.env` руками:

```
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
```

и поднимите его:

```bash
docker compose --profile standalone up -d telegram-bot-api
```

Что делает `TELEGRAM_LOCAL: "1"` в описании службы: включает локальный режим —
в нём и снимаются пределы на размер файла. Принятые и отданные файлы сервер
хранит у себя, в томе `portal_telegram_bot_api`; том растёт, и на маленьком
диске за ним стоит следить.

Порт 8081 наружу не выставлен намеренно: сервер нужен только контейнерам
портала, а открытый Bot API — это открытый доступ к вашим ботам.

## 3. Переезд бота на свой сервер

Бот живёт либо в облаке, либо на своём сервере. **Смешивать нельзя**, и
переключение делается в одну сторону явно:

```bash
curl -s https://api.telegram.org/bot<токен>/logOut
```

После `logOut` бот сразу работает на своём сервере. Вернуться в облако можно
**не раньше чем через 10 минут** — площадка держит паузу, и это не ошибка.

## 4. Настроить портал

В `.env` портала:

```
TELEGRAM_API_URL=http://telegram-bot-api:8081
```

Адрес — имя службы из compose: контейнеры видят друг друга по именам внутри
своей сети. Затем перезапустите портал:

```bash
docker compose up -d api worker
```

Перезапуск нужен не только ради настройки: при старте портал заново
регистрирует вебхук бота — и делает это уже на своём сервере. Без этого бот
молчал бы на нажатие «Start» у зрителя.

## 5. Проверка

**Кабинет → Настройки → Площадки → «Канал Telegram» → «Проверить связь».**
Кнопка спрашивает у сервера `getMe` по настроенному адресу и отвечает именем
бота. Это самая быстрая проверка: она показывает и что сервер жив, и что портал
ходит именно к нему.

Дальше — по делу: экран урока → «Загрузить видео в Telegram». Запись уйдёт вам
в личку, а рядом с кнопкой появится ссылка для зрителей.

## Если не работает

**`401 Unauthorized`.** Бот ещё числится за облаком: сделайте `logOut` (шаг 3).
Тот же ответ бывает, если в `.env` токен другого бота.

**`connection refused` или «сервер Telegram Bot API недоступен».** Портал не
видит контейнер: проверьте, что служба поднята (`docker compose ps
telegram-bot-api`), что адрес в `TELEGRAM_API_URL` — имя службы, а не
`localhost`, и что оба контейнера в одной сети.

**Снова `413: Request Entity Too Large`.** Портал по-прежнему ходит в облако:
значит `TELEGRAM_API_URL` не подхватился. Проверьте, что перезапустили
контейнеры после правки `.env`, и что в значении нет пробела или кавычек.

**Бот молчит на «Start».** Вебхук зарегистрирован на прежнем сервере.
Перезапустите api — портал регистрирует его при старте — и посмотрите в журнал:
там будет строка «Бот слушает обновления портала».

## Про этот проект

На боевой машине сервер Bot API вынесен в отдельный сервис, общий для всех
ботов хозяйства: профиль `standalone` в портале тогда не включается, а адрес в
`TELEGRAM_API_URL` указывает на общий контейнер. Для читателя репозитория это
деталь: своя копия портала поднимает сервер профилем `standalone`, как описано
выше.
