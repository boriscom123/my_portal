# Урок в каналы частями видео — дизайн

Дата: 2026-09-11. Статус: пять разделов согласованы с заказчиком в Telegram по
одному, документ ждёт его прочтения.

Опирается на то, что уже сдано: анонсы урока в каналы Telegram и MAX
(`src/jobs/publish-channel.js`, `src/services/platforms/telegram-channel.js`,
`src/services/platforms/max-channel.js`), отправку коротких роликов видео в оба
канала, монтаж без пауз (`src/jobs/trim-pauses.js`, `src/lib/trim.js`), главы
урока (`src/lib/chapters.js`) и общий слой Docker на сервере
(`/home/boris/projects/ClaudeDocker`).

## 1. Что делаем

Урок уходит в каналы Telegram и MAX самим видео, которое смотрят прямо в
ленте, — частями, прикреплёнными к одному сообщению со списком глав. Анонс
урока остаётся как есть; пост с частями идёт следом, отдельной кнопкой.

Зачем части. Бот Telegram отправляет файл до 50 МБ, MAX принимает до 250 МБ, а
урок весит сотни мегабайт: урок 8 сентября — 39 минут, 673 МБ. Для Telegram
предел снимается своим сервером Telegram Bot API — до 2000 МБ на файл; у MAX
своего сервера нет.

Готовым считается так: с экрана урока в оба канала заказчика ушёл пост с
видео урока, части смотрятся в ленте, под ними список глав и ссылка на урок.

## 2. Порядок работ

1. **Свой сервер Telegram Bot API** в общем слое и адрес сервера в портале;
   бот портала переезжает на него.
2. **Отрезки монтажа и время глав**: портал запоминает отрезки, оставленные
   монтажом, и пересчитывает главы под смонтированную запись — и для нарезки,
   и для описания на YouTube.
3. **Нарезка** записи по размеру и главам.
4. **Пост в Telegram** — кнопка и отправка.
5. **Пост в MAX** — кнопка и отправка.
6. **Живая проверка** в каналах заказчика.

Каждая часть выкатывается на сайт сразу после фиксации.

## 3. Границы

### Делаем

- Сервис `telegram-bot-api` в общем слое ClaudeDocker и тот же сервис под
  профилем `standalone` в `docker-compose.yml` портала.
- Одну настройку адреса Bot API, по которой ходят все обращения бота портала.
- Сохранение отрезков монтажа и пересчёт глав, включая описание YouTube.
- Нарезку без пережатия, по размеру и главам.
- Кнопки «Telegram — видео урока» и «MAX — видео урока» на экране урока.

### Не делаем

- Пережатие видео ради размера: режем в исходном качестве.
- Правку поста с частями после отправки: ссылки на YouTube по-прежнему
  дописываются только в анонс.
- Отправку частями новостей и коротких роликов — только уроки.
- Перевод на свой сервер ботов других проектов: они подключатся сами.
- Автоматическую отправку частей следом за анонсом — только кнопкой.

## 4. Свой сервер Telegram Bot API

**Сервис.** В `ClaudeDocker/docker-compose.yml` — `telegram-bot-api` по образцу
общих `postgres` и `redis`:

- образ закреплён: `aiogram/telegram-bot-api:10.3`;
- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из `.env` общего слоя,
  `TELEGRAM_LOCAL=1` — режим, в котором сервер принимает файлы до 2000 МБ;
- том `telegram_bot_api_data` на `/var/lib/telegram-bot-api` (владелец внутри —
  uid 101);
- сеть `data` (`shared-data`), порт 8081 наружу не публикуется;
- `restart: unless-stopped`.

Проекты обращаются по полному имени контейнера —
`http://shared-telegram-bot-api-1:8081` (короткие имена в общих сетях однажды
уже указали на два разных сервера, см. README ClaudeDocker).

**Ключи.** `api_id` и `api_hash` берутся на my.telegram.org → API development
tools. В `.env.example` общего слоя — пустые `TELEGRAM_API_ID=` и
`TELEGRAM_API_HASH=` с комментарием, где их взять. Реальные значения заказчик
вписывает в `ClaudeDocker/.env` на сервере сам: через Telegram их не присылать —
история переписки уходит в публичный репозиторий.

**Портал.** `TELEGRAM_API_URL` в окружении → `config.telegram.apiUrl`, пусто —
`https://api.telegram.org`. По этому адресу ходят все обращения бота портала:
уведомления (`src/services/notify/telegram.js`) и посты в каналы
(`src/services/platforms/telegram-channel.js`). Бот, переехавший на свой сервер,
не должен ходить в облако — смешивать нельзя.

**Standalone.** В `docker-compose.yml` портала — такой же сервис под профилем
`standalone`: на чистой машине портал поднимается целиком, как с базой и Redis.

**Переезд бота.** Разово: `logOut` у облачного Bot API для токена бота портала
(и для отдельного бота канала, если его токен задан в настройках), затем
`TELEGRAM_API_URL` на свой сервер. По документации Telegram после `logOut` бот
сразу работает на своём сервере, а в облако вернуться может только через 10
минут.

**Откат.** `TELEGRAM_API_URL` возвращается к облаку; бот снова работает через 10
минут после `logOut` или сразу, если прошло больше. Потерять бота этим нельзя.

**Проверка связи.** В блоке канала Telegram на странице настроек — кнопка
«Проверить связь»: `getMe` по настроенному адресу, ответ «на связи, бот @…» или
причина.

## 5. Отрезки монтажа и время глав

**Сейчас** главы считаются по репликам исходной записи, а на YouTube и в каналы
уходит смонтированная — без пауз. Главы в описании YouTube поэтому «убегают»
вперёд на сумму вырезанных до них пауз. Отрезки, оставленные монтажом, шаг
монтажа вычисляет (`keepRanges`) и выбрасывает.

**Будет:**

- Шаг монтажа сохраняет отрезки в `lessons.generated.trimRanges`
  (`[{ startedMs, endedMs }]`).
- Для уроков, смонтированных раньше, отрезки считаются один раз заново тем же
  путём, что сейчас пересобирает субтитры: `detectSilence` по звуковой дорожке,
  а если её уже нет (она живёт 3,5 дня), — по самой записи; результат
  сохраняется.
- `chaptersForVideo(lesson, videoAsset)` — главы на шкале уезжающего файла: у
  смонтированной записи время переводится `mapTime`, у исходника — как есть.
  Этим пользуются и нарезка, и описание YouTube.
- Монтаж ставит опорный кадр каждые 2 секунды
  (`-force_key_frames "expr:gte(t,n_forced*2)"` в `ffmpegArgsForTrim`): тогда
  граница части у смонтированной записи сдвигается не больше чем на 2 секунды.
  Касается уроков, смонтированных после этой правки.

## 6. Нарезка

Режем без пережатия (`-c copy`, начало по опорному кадру). Граница части
сдвигается к ближайшему опорному кадру раньше главы: у записей заказчика
опорный кадр каждые 5 секунд (проверено `ffprobe`), у новых смонтированных — каждые
2. Часть начинается чуть раньше главы — ничего не теряется.

**Цель — как можно меньше частей.** Предел части `limit` — предел площадки с
запасом 5%: Telegram 2000 МБ, MAX 250 МБ.

1. Файл целиком не больше `limit` — не режем: одна часть.
2. Иначе части собираются из глав подряд. Часть начинается с очередной главы и
   набирает следующие, пока оценка по среднему весу минуты помещается в
   `limit`. Оценке не верим: часть **режется на самом деле и взвешивается**. Не
   влезла — убираем последнюю главу и режем снова; влезла с запасом больше 15%
   и есть следующая глава — пробуем добавить её. Резка без пережатия идёт
   секунды, поэтому примерка дешёвая. Средний вес не годится как ответ: у
   записи экрана он «плавает» — неподвижный экран лёгкий, движение тяжёлое.
3. Одна глава сама больше `limit` — делится на наименьшее число равных по
   времени кусков `k = ⌈размер / limit⌉`; кусок не влез — `k + 1`.
4. Глав нет (или они не проходят `validChapters`) — запись делится так же, как
   одна большая глава.

Жадная набивка глав подряд даёт наименьшее число частей при резке по порядку.
Пример — урок 8 сентября, 673 МБ: в Telegram одна часть, в MAX — три.

Больше 10 частей для Telegram (предел альбома) при пределе 2000 МБ означает
запись больше ~19 ГБ; такая отправка отказывает с понятной причиной.

Части — временные файлы `lesson-<id>/parts/<площадка>-<n>.mp4`; удаляются после
отправки и при отказе. Подписи частей: «Часть 2 из 3 · Настройка nginx», при
склеенных главах — «Главы 3–4 · …», при делённой главе — «Глава 2 · 1 из 2», без
глав — «Часть 1 из 4».

Запись урока живёт в буфере неделю (`MEDIA_TTL_HOURS=168`); если её нет — отказ
«запись удалена по сроку, загрузите заново».

## 7. Пост в Telegram

- Публикация — отдельная «площадка» `telegram_parts`: своя строка на экране
  урока «Telegram — видео урока», своё состояние и защита от второй отправки,
  не путаясь с анонсом (экран и правка анонсов ищут публикацию по площадке).
- Кнопка активна, когда анонс в Telegram опубликован и уезжающая запись лежит в
  буфере. После отправки кнопка исчезает, при отказе — «Отправить заново».
- Одна часть — `sendVideo`; от 2 до 10 — `sendMediaGroup` (альбом: одно
  сообщение, одно уведомление, уходит целиком одним запросом).
- `supports_streaming: true`; превью первой части — обложка урока параметром
  `cover`.
- Подписи: у каждой части — её глава. У первой (она видна под альбомом) —
  заголовок урока, список глав с номерами частей и ссылка на урок. Предел
  подписи — 1024 знака: при переполнении укорачиваются названия глав с «…»,
  ссылка остаётся всегда.
- Отправка через свой сервер Bot API: части передаются по внутренней сети.

## 8. Пост в MAX

- Публикация — «площадка» `max_parts`, строка «MAX — видео урока», условия
  кнопки — как у Telegram (анонс в MAX опубликован, запись в буфере).
- Предел части — 250 МБ (по записи в `docs/channels-setup.md`; в документации
  MAX предел не найден).
- Каждая часть грузится в два шага, как у коротких роликов
  (`POST /uploads?type=video`, затем файл), по одной за раз.
- Пост — одно сообщение: текст (заголовок, список глав с номерами частей,
  ссылка на урок; предел MAX — 4000 знаков, влезает целиком) и все части
  вложениями по порядку.
- **Если MAX откажет в нескольких видео в одном сообщении** — части уходят
  постами подряд: первый с текстом и частью 1, следующие — «Часть 2 из 3 ·
  глава». Выбранный способ портал запоминает в настройках канала MAX
  (`platform_apps.settings.multiVideo`) и дальше отправляет сразу так.
- Ход отправки постами подряд хранится в публикации (`publications.details`:
  какие части ушли и номера их постов). «Отправить заново» продолжает с части,
  которая не ушла, без дублей.

## 9. Отказы

- Свой сервер Bot API не отвечает — «сервер Telegram Bot API недоступен»;
  проверка связи в настройках.
- Запись удалена по сроку — «загрузите запись заново».
- Запись не режется (битый файл) — причина словами, через `describeFailure`, а
  не код ffmpeg.
- MAX не принял несколько видео — не отказ: переход на посты подряд.
- Сбой посередине постов подряд — продолжение с непришедшей части.
- Отказ пишется в публикацию (`error`) и показывается под кнопкой, как у
  анонса.

## 10. Данные

Миграция:

- `publications.platform` — допустимые значения дополняются `telegram_parts` и
  `max_parts`: ограничение `publications_platform_check` снимается по имени и
  ставится заново со списком `youtube, vk, telegram, rutube, tiktok, instagram,
  dzen, max, telegram_parts, max_parts` (сейчас в нём первые восемь — проверено
  по живой базе);
- `publications.details jsonb NOT NULL DEFAULT '{}'` — ход отправки постами
  подряд.

Без миграции: `lessons.generated.trimRanges`,
`platform_apps.settings.multiVideo` (у MAX).

## 11. Чем проверяется

Тесты без походов в сеть; ffmpeg подставляется там, где проверяется логика, а
не резка:

- нарезка: «влезает целиком — не режем», «главы набиваются до предела», «часть не
  влезла — убираем главу», «влезла с запасом — добавляем», «глава больше
  предела», «глав нет»; подставные размеры частей;
- пересчёт глав под смонтированную запись и описание YouTube;
- подписи: предел 1024 у Telegram, ссылка на урок остаётся;
- одно видео против альбома;
- MAX: одним сообщением; запасной путь постами подряд; продолжение после сбоя;
- кнопки на экране урока и защита от второй отправки;
- адрес Bot API из настроек — и уведомления, и посты ходят по нему;
- опорный кадр каждые 2 секунды в аргументах монтажа.

Проверка перед фиксацией — по `CLAUDE.md`: все тесты в несколько потоков и
линтер в образе `my_portal-worker`. Живая проверка: заказчик вписывает ключи,
сервер Bot API поднимается, бот переезжает, урок уходит частями в оба канала;
отчёт говорит, что проверено вживую, а что нет.

## 12. Открытые вопросы

1. **Несколько видео в одном сообщении MAX** — документация молчит; решается
   первой живой отправкой, запасной путь описан в разделе 8.
2. **Предел видео у MAX** — 250 МБ взяты из нашей записи; если живая отправка
   покажет другой, предел поправляется одной константой.
3. **Отдельный бот канала Telegram.** Если в настройках задан свой токен бота
   канала, он переезжает на свой сервер так же; если он же используется где-то
   вне портала, переезд его там сломает — заказчик подтверждает перед
   переездом.
4. **Память сервера** (3,8 ГБ на всё): сервер Bot API берёт ~50–100 МБ; нарезка
   без пережатия память почти не ест. Проверяется после выкладки по
   `docker stats`.
